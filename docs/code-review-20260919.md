# 四端代码复审与 Android 解锁修复（2026-09-19）

## 审查范围

应用代码基线 `71b2c8143870ab57420be3c407bab47e2ae02a48`；只读 CI 快照 `6029b726dc898e878b184e08732073a1c954f106`。审查重点是启动/解锁、载入状态、本地加密与落盘、同步提交、锁定时异步结果、Web 分页/合并单元格以及发布校验。不把静态审查等同于所有设备、全量图片或真实 WebDAV 环境的实测。

## 本次修复

### Android：解锁后误显示空卡包（P1）

`MainActivity` 原来仅根据安全锁决定是否打开导航；`SyncCoordinator` 锁定时把卡片流清空，解锁后后台读取 SQLite，再读取同步历史、解密配置，最后才发布卡片。`MainScreen` 没有区分尚未载入与零张卡片，且在组合过程中再次同步读取云配置。因此健康的卡片会被慢/损坏的附属数据拖延，真实空态、新增入口、提醒也可能提前出现。

修复增加独立的 Loading/Ready/Error/Locked 状态和本地单次载入器。本机卡片成功读取后立即发布，再加载历史与配置；这些附属数据失败不回退已读卡片。读取失败保留原库并提供重试，不请求云端覆盖。锁定取消加载、清空内存卡片；以会话代次拒绝旧的本地加载结果，逐条/逐块检查取消。首页同步就绪状态改为观察状态流，不再在组合中解密配置。

`AndroidLocalDataCipher` 原先每个加密块均调用 KeyStore.load/getKey。现在一个短生命周期实例复用不可导出的系统密钥句柄；密钥字节不导出、AES-GCM/随机 IV/用途验证不变。原密钥缺失或失效仍失败，不创建替代密钥掩盖错误。未声称十多秒已经在用户设备上缩短到某个具体数值。

### Android：锁定或离开页面后返回 NFC 结果（P2）

读卡前已有锁检查，但后台线程结束时没有复查。新增结果交付时对前台状态和安全锁的检查，防止当前已锁定页面继续分发卡号或弹出成功提示。本次没有更改 NFC 协议和卡片数据格式。

### Web：最新高亮实现与浏览器断言不一致（P2）

最新主线使用“悬停行 + 跨行共享单元格”的多个不重叠光带，测试仍假定全组只有一个光带，导致严格选择器/几何断言失效。保留维护者最近的界面修改，改为检查唯一行光带、合并银行块的覆盖并集及离开后的清理；分页和收藏用例保留。文档同步真实行为。

## 保留的正确性与验证边界

四端的 SyncV4 字段/记录标识、图片未来字段保留、单调修改时间、墓碑合并与原子存储测试保留；Android 仍采用事务写入，Apple 账本在成功保存候选值后替换内存状态，Web 的保险库会话与跨页选择路径没有重写。发布仓库、版本、安装标识及新签名 Secrets 不变；不自动覆盖已经发布的安装包。

提交前验证运行 `35428060704`：Android 的 21 个测试套件共 97 项测试（包括新增 8 项加载状态/竞态测试和 2 项 Compose 测试）、Debug 构建、Lint、设备测试包编译均通过；Web 的 29 个测试文件共 274 项测试、生产构建及三套浏览器回归均通过。导出的 16 份源码对象已与本地审阅版本逐一核对。实际 AndroidKeyStore 测试的设备执行和 Apple 原生测试由最终提交的 Platform quality 继续验证，结果以对应提交的 Actions 结论为准。

本次不包含用户设备性能定量结论，也没有直接访问用户卡片或 WebDAV 凭据。修复不要求卸载应用、清空卡片或重新生成签名。真机验收应保留原数据，分别验证冷启动密码解锁、生物识别、离线解锁、快速重复锁定/解锁，以及含图片卡片；后续正式更新继续使用相同签名，并按发布规则递增构建号。
