## 本次修复

### Android：解锁后误显示空卡包（P1）

`MainActivity` 原来仅根据安全锁决定是否打开导航；`SyncCoordinator` 锁定时把卡片流清空，解锁后后台读取 SQLite，再读取同步历史、解密配置，最后才发布卡片。`MainScreen` 没有区分尚未载入与零张卡片，且在组合过程中再次同步读取云配置。因此健康的卡片会被慢/损坏的附属数据拖延，真实空态、新增入口、提醒也可能提前出现。

修复增加独立的 Loading/Ready/Error/Locked 状态和本地单次载入器。本机卡片成功读取后立即发布，再加载历史与配置；这些附属数据失败不回退已读卡片。读取失败保留原库并提供重试，不请求云端覆盖。锁定取消加载、清空内存卡片；以会话代次拒绝旧的本地加载结果，逐条/逐块检查取消。首页同步就绪状态改为观察状态流，不再在组合中解密配置。

`AndroidLocalDataCipher` 原先每个加密块均调用 KeyStore.load/getKey。现在一个短生命周期实例复用不可导出的系统密钥句柄；密钥字节不导出、AES-GCM/随机 IV/用途验证不变。原密钥缺失或失效仍失败，不创建替代密钥掩盖错误。未声称十多秒已经在用户设备上缩短到某个具体数值。

### Android：锁定或离开页面后返回 NFC 结果（P2）

读卡前已有锁检查，但后台线程结束时没有复查。新增结果交付时对前台状态和安全锁的检查，防止当前已锁定页面继续分发卡号或弹出成功提示。本次没有更改 NFC 协议和卡片数据格式。

### Web：最新高亮实现与浏览器断言不一致（P2）

最新主线使用“悬停行 + 跨行共享单元格”的多个不重叠光带，测试仍假定全组只有一个光带，导致严格选择器/几何断言失效。保留维护者最近的界面修改，改为检查唯一行光带、合并银行块的覆盖并集及离开后的清理；分页和收藏用例保留。文档同步真实行为。

以上三项已随 `22706f54605695d1996726b4dec53340a6d3f733` 进入主线，后续保留回归和真机验收，不重复安排同一修复。

### 后续已完成：macOS 锁定内存会话（P2）

`16e2dd1807743b1b6bd165971f9fb5b39ca13f81` 已包含 macOS 锁定后的卡片/账本/历史与附件缓存释放、旧会话回调拒绝及解锁再载入。详情见 [macOS 锁定内存修复](macos-lock-memory-20260919.md)。这项从待修复列表移出，只作为后续异步读盘优化的回归约束；它没有改变本地磁盘加密和凭证存储模式。

## 已确认的设计决策：macOS 保留本地加密存储

维护者于 2026-09-19 明确决定：macOS 继续使用 `LocalDataCipher`、`LocalCredentialStore` 的现有本地加密文件方案，不使用系统钥匙串作为正常存储后端。移除原复审中“macOS 同目录保存密钥，需要迁移 Keychain 或密码派生封装”的待整改项，不再赋予待修复优先级，也不另列为延期修复。

密钥与密文同时被复制后，现有方案不能阻止持有两者的人离线解密，这是已接受的设计边界，不把它误写成已被技术消除。保留本地加密、文件权限与读写失败保护；不删除旧密钥、不清空数据、不自动更换格式。除非维护者另行明确改变决定，后续审查不得仅因此再次提出存储后端迁移。真实泄漏或实现错误仍需处理。

这项决定已写入根目录 [开发约定](../AGENTS.md) 和 [macOS 说明](../apps/macos/README.md)。现有 `KeychainManager` 名称/旧版本单向迁入兼容不改变这一决定；发布签名 Secrets、iOS 既有存储和 Android Keystore 不属于这项移除范围。

## 分阶段实现与验收范围（按执行顺序）

### 第一阶段：iOS 锁定会话与恢复

状态：已完成并提交 `4deddbcf`，阶段二继续保持该会话边界。以下为实现与回归要求。

- 锁定时取消在途读取/同步/图片工作，释放协调器及界面持有的卡片、账本、同步历史、详情/编辑和附件缓存；覆盖已打开弹窗、后台切换和各窗口/场景的引用，不更换 iOS 的既有存储后端。
- 会话标记跨越每个异步恢复点进行校验；解锁后区分 Loading/Ready/Error，完成本机卡片及必要账本的恢复后才开放编辑和恢复同步。同步历史、配置和网络不能把健康的本地列表卡成空态。
- 不把锁定产生的空列表落盘、转成删除记录或上传；保留已提交修改、墓碑和待上传状态。读取失败保留原文件并提供重试，未经确认的编辑草稿沿用原有保存/取消规则。

验收：冷启动保持锁定时不读取业务卡片；离线解锁可恢复；下载/图片解码期间锁定和快速反复解锁后旧结果均被拒绝；原数据、删除记录及待上传标记不丢失。只承诺释放应用可控的明文引用，不声称物理内存中的每个副本都已逐字节归零。

### 第二阶段：iOS/macOS 启动与本地读写性能

状态：已完成并提交 `1209d1cb`，保留第一阶段及 macOS 已有的锁定会话保护。以下为实现与回归要求；真实设备计时不作已完成声明。

- 在相同设备和数据集上记录冷启动、解锁到本地首屏、读取、解密/解析、主线程占用及内存峰值；覆盖普通卡片、较多记录和含图片数据，不把 CI 耗时当成真机体验。
- 将阻塞读盘、解密、JSON 解析及账本恢复放入各端串行存储队列/任务中。主线程只切换加载状态和提交当前会话的结果；本地数据优先于历史展示、云配置和网络同步。账本中的删除记录仍是必要数据，不能为提速跳过。
- 对保存链路逐步移除主线程同步等待：候选结果成功持久化后才替换内存并报告成功，保留修改顺序、原子写入、异常恢复和取消语义；不简单地并发启动所有读写。
- macOS 严格保持现有本地加密文件、密钥、路径和权限；不新增钥匙串访问、不更换加密存储后端、不重新生成用户密钥。

验收：可观察的耗时磁盘/解密工作不再占用主线程；界面在大数据载入时仍能响应。重复载入、快速编辑、载入中锁定、磁盘写入失败和重启均不产生旧结果回填、空库覆盖或写入乱序。性能结论必须提供相同条件下的前后对比，不预先宣称具体秒数。

### 第三阶段：Android PIN 校验平滑升级

状态：已完成并提交 `00ef95dd`。只改变 PIN 校验记录，不把它改造成密码派生的数据保险库。以下为实现与回归要求。

- 新增版本化校验记录，保存独立随机盐、KDF 标识/参数和校验值；使用成熟的慢速 KDF，不自制算法，参数在目标设备基准测试后确定并记录。
- 旧格式仅在用户输入正确 PIN 后升级；先验证并原子保存新记录，成功后才移除旧校验值。失败不遗失原有解锁能力，不在日志保存 PIN 或派生值；生物识别成功不能凭空取得 PIN，因此延后到下一次正确 PIN 验证再迁移。
- 派生和验证移出主线程，处理重复点击、并发验证及验证中锁定；保留现有错误次数/冷却机制、数字 PIN 规则和生物识别入口，新增提示同步现有语言资源。

验收：旧 PIN 无需重设，新记录重启后可验证；错误 PIN、错误/未知格式和中断迁移不能绕过锁屏；新格式不可静默降级。原有卡片、Android Keystore、云端同步口令及发布签名保持不变。慢速校验只提高猜测成本，不宣称数字 PIN 变成了高熵密钥。
