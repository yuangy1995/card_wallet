## 阶段二：Apple 本地存储串行异步化

状态：已提交主线 `1209d1cb4a8842dc34befe8f34f465ca87d8d3d9`。运行 `35452254120` 中 iOS 36 项、macOS 115 项原生测试均通过，零失败、零跳过；26 份导出源文件已核对。本阶段提交同时移除临时验证任务，恢复 Signing security 的只读权限。

iOS/macOS 的启动读卡、账本载入、解密/解析及保存移入专用串行存储执行器。主线程事务门跨越“读取当前值→生成候选→持久化→发布”保持串行，避免 actor 在 await 期间重入而丢失更新。锁定前已进入的原子写入允许完成，下一次解锁读取等待其完成；旧会话不接收 UI 成功通知。其他未开始的队列工作以会话标记拒绝。

健康的同步账本作为权威数据源；已存在时不重复解密 cards.json、不在打开时重写完整卡片库。旧安装没有账本时仍从原卡片文件恢复；账本损坏不回退到过期副本。卡片镜像写入失败不回滚已成功持久化的权威账本，给出提示，下一次离线载入仍恢复已提交数据。同步确认元数据与编辑使用同一事务门，不将旧上传快照合并回来覆盖新编辑。

本机列表恢复优先于同步历史和网络，编辑页在保存成功后才关闭，失败不报告成功。受控阻塞读/写测试验证主线程在存储线程被阻塞时仍可运行；另覆盖并发修改、同步确认、锁定中的读写、失败不发布及权威账本恢复。数据密钥、macOS 本地加密后端、目录、随机 IV、文件权限及 SyncV4 格式均不改变。

## 阶段三：Android PIN 校验平滑升级

状态：已提交主线 `00ef95ddeff30883103ac444ef922138745c6ff2`。提交前专项运行 `35453232924` 成功，117 项单元/界面测试、6 项 Android 34 设备测试通过，Debug 构建、Lint 和设备测试包编译通过；10 份源码对象来自同一经验证补丁。单元迁移用例同时覆盖 Android API 23 与 34。

新增 `pin-v2` 版本记录，使用 16 字节随机盐、PBKDF2-HMAC-SHA256、600000 次迭代和 32 字节校验值。算法用固定版本 Bouncy Castle 轻量实现，Android 23–25 也使用同一格式，不注册全局 Provider。常量时间比较校验值，解析器限制记录大小与迭代上限，未知版本/异常记录拒绝验证，不回退旧 SHA-256。参数依据 OWASP 的 PBKDF2 建议；设备测试核验正确性，未把模拟器耗时描述成真实手机基准。

仅正确输入旧 PIN 时生成新记录，一次原子持久化同时写入新记录/版本并移除旧校验值；保存失败恢复原校验记录，保留原有解锁能力。生物识别保留，但不能据此生成 PIN，迁移延后到下一次正确 PIN 输入。关闭安全锁改为一次带密码验证的原子操作，避免先解锁后另行清空的竞态。

KDF、验证和持久化在后台执行；串行化密码操作，保留尝试次数与冷却机制，离开页面/锁定/生物识别成功使旧任务失效。界面防止重复提交并在离开时取消，新增错误文案加入现有语言资源。卡片数据库、Android Keystore、同步口令和发布签名不变，不要求重设 PIN、卸载或清空卡片。慢速校验提高猜测成本，不宣称数字 PIN 具备高熵。

参考：[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[SharedPreferences.Editor 原子提交](https://developer.android.com/reference/android/content/SharedPreferences.Editor)。
