## 阶段一：iOS 锁定会话与恢复

状态：已提交主线 `4deddbcfa920ced7ecae4b58bb126514b70e7edb`。提交前运行 `35446542356` 的 iOS 原生构建及 27 项测试全部通过（含新增 9 项会话测试）。

实现独立的 Locked/Loading/Ready/Error 加载状态。冷启动锁屏不读卡，卡片与必要账本恢复成功后才显示可编辑钱包；历史失败不隐藏健康的卡片。锁定立即撤销会话、取消在途任务/请求和计时器，释放 cards/ledger/history；空的锁定状态不落盘。旧会话的同步结果、错误处理与进度回调不能在下一次解锁后修改内存或文件。通知在系统授权等待前投影为日期、ID 和数量，不跨等待持有完整卡片；已排程通用通知保留。图片导入/识别任务在离开页面时取消并验证原会话，卡号计时器离开时释放。

隔离存储测试覆盖冷锁无读写、锁定释放且不写空库、离线恢复墓碑和待上传标记、旧会话拒绝、读卡/账本错误、历史失败、真实空钱包及重复恢复。保留既有存储格式和 iOS 存储后端。只承诺释放应用可控的引用；系统/图像/密码库中已运行的短时操作需要返回后释放临时副本，不宣称逐字节擦除。

## 阶段二：Apple 本地存储串行异步化

状态：代码和原生 CI 验证完成。运行 `35452254120` 中 iOS 36 项、macOS 115 项原生测试均通过，零失败、零跳过；26 份导出源文件已核对。本阶段提交同时移除临时验证任务，恢复 Signing security 的只读权限。

iOS/macOS 的启动读卡、账本载入、解密/解析及保存移入专用串行存储执行器。主线程事务门跨越“读取当前值→生成候选→持久化→发布”保持串行，避免 actor 在 await 期间重入而丢失更新。锁定前已进入的原子写入允许完成，下一次解锁读取等待其完成；旧会话不接收 UI 成功通知。其他未开始的队列工作以会话标记拒绝。

健康的同步账本作为权威数据源；已存在时不重复解密 cards.json、不在打开时重写完整卡片库。旧安装没有账本时仍从原卡片文件恢复；账本损坏不回退到过期副本。卡片镜像写入失败不回滚已成功持久化的权威账本，给出提示，下一次离线载入仍恢复已提交数据。同步确认元数据与编辑使用同一事务门，不将旧上传快照合并回来覆盖新编辑。

本机列表恢复优先于同步历史和网络，编辑页在保存成功后才关闭，失败不报告成功。受控阻塞读/写测试验证主线程在存储线程被阻塞时仍可运行；另覆盖并发修改、同步确认、锁定中的读写、失败不发布及权威账本恢复。数据密钥、macOS 本地加密后端、目录、随机 IV、文件权限及 SyncV4 格式均不改变。

阶段三（Android PIN）和阶段四（综合回归）待继续。真实设备的 Touch ID/Face ID、系统授权以及大图片性能对比仍需设备验收；自动化测试不能代替这些结果。没有用户设备访问，本轮不提供虚构的具体解锁提速秒数；操作数减少和线程/原子性测试也不等于不同设备上的耗时保证。
