# macOS 锁定内存修复（2026-09-19）

基于主线 `22706f54605695d1996726b4dec53340a6d3f733`。此次只处理 macOS 的锁定内存保留及其恢复/异步交付，不改变 iOS、Android、Web 或磁盘加密格式，也不轮换签名密钥。

## 修复内容

- `SyncCoordinator` 锁定时释放完整账本（包含活动卡片和墓碑）、回调和延迟上传任务，重置启动状态。冷启动锁定时拒绝读账本；重新解锁后必须从原存储加载成功才能配置同步，旧会话的读取/合并回调即使晚到也失效。空的锁定状态从不落盘。
- `ContentView` 锁定时清空自身卡片、编辑/详情、提醒队列、搜索和筛选选择，取消延迟编辑和通知刷新，不再于锁屏下调用初次读卡。解锁重新加载，读取失败保留原库并显示既有重试界面。锁定不使用退出动画保留业务画面。
- `WebDAVBridgeService` 不再在单例初始化中解密历史，锁定清空内存历史、进度及提供者回调；恢复时重新加载原历史。网络回调持有可撤销的数据容器，锁定撤销其中的下载快照、上传记录及同步口令，不等待网络结束才释放这些长期引用。
- `CardImageCache` 清除已解码附件，取消在途解码并验证会话代次，防止清理后旧结果重新写入缓存。历史凭证读取缓存也释放，但不删除本地文件或 Keychain 项。
- `CardSystemNotificationCenter` 取消刷新、清空排队卡片；后台先生成仅含日期、ID 和数量的提醒投影，不让完整卡片、CVV、图片跨越系统授权等待。各个异步恢复点检查撤销，现有通用系统提醒不因锁定而删除。

## 正确性边界

释放应用持有的引用不等于保证物理内存每个字节归零；已经进入系统加密/图像解码的短时工作需要退出后才释放临时副本。已发往服务器的请求不能被撤回，但旧回调不能重建新会话或写回账本。这不是磁盘密钥迁移；先前复审中的 macOS 同目录密钥风险和 iOS 内存会话问题未在本次顺带修改。

新增 `LockMemoryTests` 使用隔离存储/桥接替身与合成图片验证：真实账本引用释放、锁定不写空库、冷锁不读盘、恢复墓碑与待上传标记、旧会话回调拒绝、失败重试、反复锁定、历史惰性读取与恢复、撤销容器释放和迟到追加、缩略图缓存清理及解码期间锁定。原测试保留，附件测试使用隔离的锁状态而非访问实际用户凭证。最终结果以对应提交的 GitHub CI 为准。
