# 四端代码复查与 Android 解锁修复（2026-09-19）

审查基线：`71b2c8143870ab57420be3c407bab47e2ae02a48`。重点是四端启动、锁定、解锁、本地加密读写、同步提交边界和近期 Web 收藏分页改动；不是穷尽全部代码、依赖和设备的安全认证。未读取真实卡片或 WebDAV 账户。

## Android 修复

1. `MainActivity` 以前仅按 locked 挂载页面，协调器锁定时清空列表，异步读取结束前被显示为真实空卡包。新增 NOT_LOADED/LOADING/READY/FAILED：读取成功才进入卡包，失败显示保留原数据的重试提示，不提供空卡包操作。
2. 本机卡片读取后立即发布，不等同步历史、配置或网络初始化；辅助数据损坏不隐藏卡片、不覆盖原配置。首页与设置首页不再在 Compose 初始化时重复解密云端配置，只观察后台提供的不含凭据的同步就绪状态。
3. 合并重复加载请求，锁定使旧会话 token 失效；旧任务不能在再次解锁后回填卡片、历史或失败状态。每个加密分块检查会话，与本地写入串行，避免旧快照覆盖刚编辑的卡片。
4. 同一短生命周期 AndroidLocalDataCipher 复用 AndroidKeyStore 的不可导出句柄，减少逐块反复查询。每次仍使用独立 Cipher、随机 IV 和认证用途，没有导出密钥、缓存明文到磁盘或改变数据库格式。
5. NFC 读取完成后重新检查锁定与数据就绪，避免锁屏后发出含卡号的回调/提示。补充中英文读取提示。

没有真实设备/真实卡片的耗时剖析，不能承诺固定毫秒数。带大图片的记录仍需完整解密；旧数据库首次迁移也可能耗时。本次同时减少读取工作量、隔离辅助读取、修正空状态，不是只加 loading 遮罩。

## Web 回归检查修复

本轮实际 CI 发现 `table-controls-regression.py` 仍假定页面只有一个悬停光带，但最新主线已经改成“当前行光带 + 合并单元格补光”，触发严格选择器多匹配失败。保留维护者最新界面代码，改为验证当前行边界、多个补光区完整覆盖银行合并块、不照亮相邻卡片别名、移出清除，以及浅色/深色下的行为。收藏、分页数量、刷新记忆、移动端与卡片视图检查没有删除或跳过。

## 其余审查结果：明确待办，未顺带改变存储协议

| 平台 | 观察与风险 | 后续建议 |
| --- | --- | --- |
| Android | 部分 Compose 回调直接调用同步的 commitCardChanges，写账本、历史并再次 getAllCards；大数据可能阻塞主线程。 | 将整个本地变更 API 移到 IO 协程，仍须等事务成功才报告保存成功。 |
| macOS | ContentView.onAppear 在锁屏状态也调用 loadCards；锁定不清空视图 cards/协调器 ledger。读卡、解码与读账本是同步调用。 | 明确锁屏内存保护目标，分离异步加载状态，解锁后装载、锁定使会话失效，并补竞态测试。 |
| macOS | LocalDataCipher 明确采用同目录随机 key 文件与密文，不是密码派生保险库；目录副本同时含 key 与密文时，应用锁不防离线解密。 | 这是当前设计的安全边界，不是发布签名泄漏。改成 Keychain/密码封装需要单独设计并验证原子迁移，不能直接换密钥。 |
| iOS | @MainActor bootstrap 同步读取配置、历史、卡片与账本，RootView 仅按锁状态进入主界面；大数据可能卡首屏，失败缺少独立卡片加载重试入口。锁定暂停网络但保留 cards/ledger。 | 将磁盘解密与首屏就绪明确分开，覆盖慢历史、失败与重锁。此为代码路径风险，不声称已复现 Android 十秒症状。 |
| Web | VaultApp 在本地保险库解锁成功后挂载钱包；IndexedDB 有 session 校验且锁定清明文 cache；同步有 generation 失效检查。近期分页支持数量选择与结果变化回第一页。 | 本轮在上述路径未确认同类阻塞缺陷；保留浏览器、跨页选择和全量搜索测试，不能据此宣称没有其他问题。 |
