# Web 剩余问题修复与四端对齐方案

## 基线与范围

本次接续 PR #5（`ca0eb54dc5fd6ea976ee39d8b8549a040eadda9e`），在独立分支 `codex/web-security-performance-completion` 实现，PR #6 暂以 #5 分支为基线。先合并 #5，再把 #6 的目标分支改为 main 后合并；不要把两轮修复当成互斥替代方案。本次修改 Web、相关测试与维护文档，不修改 Android、iOS、macOS 源码、应用标识或签名材料。

上一轮报告是历史审查记录，其中“仍未修复”描述的是当时状态。本轮对应实现与验证以本文件和 PR #6 的最终检查结果为准。以下“已修复”不表示已经证明不存在其他缺陷。

## 已落实的修改

### 计算与数据正确性

- `cardMetrics.js` 统一卡片分组与统计页的额度算法：共享额度按地区、规范化银行名和币种分池取最大值，独立额度累加，储蓄卡不计入。原统计页“取第一张共享卡”的错误也一并修复。
- 不同币种分别显示，未知币种单列；不拼成带 ¥ 的伪总额，不暗示进行了汇率换算。独立额度求和使用分为单位的累加，避免常见小数累加误差。
- 表格合并只针对当前页中连续、同口径且同显示值的单元格，不跨独立卡、币种或分页边界。
- Web 列表、卡面与优惠用卡共用免息天数计算，短月份的实际账单日和当天消费归属被纳入判断；增加卡等级分组及免息期双向排序。
- Web 卡组织显示使用统一识别函数。该功能是展示提示，不是银行归属、完整 BIN 或持卡权验证；歧义文本返回未知。
- 修复短卡号显示和仅输入卡号分隔符时错误匹配所有记录的问题。
- 同一卡片连续本地修改的时间戳严格晚于已观察版本，解决同毫秒修改由随机 mutationId 决胜而丢失最新值的问题；未改变其他客户端使用的 SyncV4 冲突比较规则。

### 本地加密与锁定

- 本地卡片、同步账本、历史、快照、WebDAV 账号密码和同步密钥写入 AES-256-GCM 密文。每个保险库生成独立随机数据密钥；用户密码经随机盐与 PBKDF2-HMAC-SHA256（600000 次）派生包装密钥。运行中的 CryptoKey 不可导出。
- 旧固定盐密码仅用于首次验证；验证正确后，将本地业务数据和历史配置在单个事务中迁移，再移除旧密码校验值及旧凭证。迁移失败不删除原始数据。已加密的业务行缺少元数据时拒绝静默降级或覆盖。
- 保留原数据库名 `card-wallet-web-local-db`，升级数据库版本到 2，避免旧版客户端继续用版本 1 写入明文。升级被其他旧标签页阻塞时需关闭旧页面再重试。
- 修改本地密码需验证当前密码，只重新包装数据密钥，不改变云同步密钥，不重新加密全部图片。提交失败时原密码仍有效。
- 解锁前不挂载卡包业务界面或启动云同步；每个新标签页都必须取得自己的解密密钥。仅修改 localStorage 的“已解锁”标记不能绕过解密。
- 锁定时清除本地明文缓存和运行密钥、卸载业务界面及弹窗、关闭消息、停止上传定时器并取消网络/系统认证请求。已发送到服务器并被接受的写入不能追溯撤回。
- 系统解锁使用 WebAuthn PRF 输出包装数据密钥，并验证凭证 ID、RP ID、挑战、来源、签名和用户验证标志。只验证签名的旧凭证不能解密；设备不支持 PRF 时保留密码解锁，不退回保存明文密钥。
- 忘记本地密码不能恢复本地密文。明确确认后只重置本地数据，重新设置本地密码，再填写原 WebDAV 配置和原同步密钥恢复云端快照；不自动删除远端备份。

安全边界：需要 HTTPS 或 localhost。弱密码仍有离线猜测风险，建议使用较长且唯一的密码。上述保护针对静态存储，不防御已解锁页面中的恶意同源脚本、恶意扩展或已被控制的操作系统；JavaScript 不能保证所有字符串立即从物理内存擦除，也不能保证浏览器历史磁盘页的取证擦除。仅加密备份文件或把固定口令藏进代码不属于这套保护。

### 同步可靠性与性能

- 数据库批量事务和账本队列保证卡片、待同步标记及修改版本一起提交。多标签页写入通过版本比较拒绝旧页面覆盖新数据，并要求重新解锁加载最新版本。
- 连续本地编辑立即保存，0.8 秒内合并上传触发；下载期间的本地编辑按最新账本合并，不写回下载开始前的旧副本。上传完成只确认对应修改版本，不能清除后续编辑的待同步状态。
- 移除库实际未采用的 fetcher 配置，使用真实 AbortSignal；上传/下载 XHR 和库请求都有取消与超时处理。取消加密过程中的上传准备后，不再发起新的上传。
- 任一选中的云快照下载、解密或结构检查失败，不继续发布不完整合并，也不继续清理备份。只清理本轮确实成功读取并合并的旧快照，保留其他设备在同步期间新增的文件。
- 保持 SyncV4 4.0.0 写入格式、310000 次云端 KDF 参数和文件命名不变。四端现有写入代码均使用该参数；Web 读取增加盐/IV 长度及合理 KDF 工作量检查，拒绝恶意极端参数。
- 移除浏览器实际无法兑现的“忽略服务器证书”开关。需要服务器可信证书与正确 CORS 配置，前端不能绕开浏览器证书验证。

### 渲染、加载与输出安全

- 主表格每页 50 行、卡片列表每页 24 张；统计长列表和优惠用卡列表亦有分页。页内渲染有上限，全量搜索、汇总、CSV 导出和跨页批量选择不只处理当前页。
- 选中 ID 使用 Set；选择清理只监听 ID，不深度遍历图片对象；关闭分组卸载卡片；清理图表、事件监听、定时器及失效组件引用。
- 使用单个日历日时钟刷新跨日计算，不为每张卡片创建计时器。移除人为增加的保存和分析延迟。
- Element Plus 改为按需引入，取消强制合并所有 UI 依赖的巨大公共块。统计图表按模块引入；详情、编辑、帮助、同步等界面按打开需求加载。
- 动态 HTML 中的用户字段转义，图表 tooltip 使用富文本画布模式；CSV 转义逗号、引号、换行和危险公式前缀，空数据也能导出。
- 增加 CSP、no-referrer、减少动态效果适配。CSP 的 connect-src 仍需允许用户自定义 WebDAV 地址；部署方可进一步收紧，并用 HTTP 响应头配置 frame-ancestors（meta 中不能替代该响应头规则）。

## 验证与性能口径

本地新增测试覆盖真实 Web Crypto 加解密、迁移事务回滚、密码变更、错误密钥/篡改数据、锁定后写入、旧标签页覆盖、系统解锁 PRF 及签名校验、云端部分失败和连续修改竞态。已有测试保留。组件测试实际挂载 Vue/Element Plus，2000 条输入时主表格渲染 50 行、卡片视图渲染 24 张。

本地阶段通过 20 个测试文件、144 个用例。生产构建通过。最终 CI 与生产浏览器测试状态以 PR #6 的最新结果为准，不把本地组件模拟测试当作真实浏览器或真实生物识别设备验证。

基线与本轮的相同构建方式比较（gzip 为逐 JS 文件压缩求和，十进制 KB）：

| 指标 | PR #5 基线 | 本轮本地构建 |
| --- | ---: | ---: |
| 入口静态 import 依赖 JS gzip | 528.34 KB | 约 124 KB |
| 全部产出 JS gzip，包括按需块 | 845.85 KB | 约 546 KB |
| ECharts 块 gzip | 277.10 KB | 138.31 KB |
| 2000 张输入时主表格 DOM 行 | 全量路径 | 50 |
| 2000 张输入时卡片组件 | 全量路径 | 24 |

入口依赖统计不包含运行时随后打开的密码对话框等动态块；不等于首次交互全部网络字节。文件体积下降不等于同等百分比的页面速度提升。本地密钥派生引入了必要的解锁成本；完整数据及图片仍占用与数据规模成比例的存储和内存，分页不是无限数据量保证。

生产浏览器脚本位于 `apps/web/scripts/browser-regression.py`，仅使用合成的 2000 张卡，不连接真实 WebDAV，检查迁移、锁定、新标签页、全量搜索、分页、主题及图表按需加载。实际浏览器/设备权限、特定 WebDAV 服务器、四端实机互同步仍需对应设备及服务器验收，不能由这些测试替代。

## 四端对齐：建议按业务规则对齐，不照搬界面

### 第一阶段：先统一不会因平台而变化的规则

建立一个受版本控制的契约与测试样例目录，四端分别读取同一份 JSON 输入/期望结果；保留各端独立实现和原生 UI，不为了“共享”引入跨端运行框架。建议至少覆盖信用/储蓄分类、地区/银行/币种共享额度、空币种、日期、账单日归属、年费确认、删除标记、图片字段、同步冲突和本地锁定。

| 项目 | 怎么改 | 重点文件/端 |
| --- | --- | --- |
| 共享额度与币种 | 同地区+规范化银行名+币种分池取最大值，独立额度累加；未知币种不能自动当 CNY | Web 本轮已统一；macOS `Domain/CardCatalog.swift` 的空币种 CNY 回退应调整；Android/iOS 的全部统计入口接相同样例验证 |
| 日期规则 | 实际月末补齐，明确同日消费归属、闰年、时区和到期边界；同一张卡在各视图使用同一算法 | 四端 DateCalculator / CardReminderRules 及统计、排序入口 |
| 搜索 | 统一银行、别名、规范化卡号、等级、币种、地区、权益、备注、额度和类别；空分隔符不能变成全匹配 | iOS `Features/HomeView.swift`；macOS `Domain/CardCatalog.swift`；Android `ui/main/MainScreen.kt`；Web `App.vue` |
| 分组与排序 | 四端都有无分组/银行/地区/等级/卡组织；额度、免息期双向与最近修改；排序平局使用稳定 ID | Web 本轮补等级及免息期；Android 补免息期从短到长；其他端核对菜单和实际排序，不只检查枚举 |
| 偏好保留 | 保留用户主动选择，不用页面局部状态重置；应用版本升级不覆盖旧偏好 | iOS 的 @State 分组/排序改为持久化；Android/Web 保留既有键，macOS 核对根级绑定存储 |

不要同时改变 SyncV4 冲突规则或偷偷增加每端意义不同的字段。时间戳、删除事件、恢复覆盖与并发编辑必须先有四端契约回归，再实施需要协议演进的变更。

### 第二阶段：补齐共同操作与可见体验

**收藏：**Android 当前是本机 SharedPreferences 展示偏好，没有进入 SyncV4。建议先给 iOS、macOS、Web 补相同的本机收藏/只看收藏入口，使用稳定卡 ID，删除卡片时清理悬挂 ID；不因收藏更新卡片业务修改时间。若产品目标要求跨设备收藏，另设计带版本、时间戳和删除语义的偏好记录，四端同时支持后再启用，不能只在 Web 给 SharedCard 加一个字段就声称同步完成。

**品牌素材：**以 Android/macOS 已采用的离线素材目录与匹配表为维护来源，生成或复制为各平台原生资源；iOS/Web 接入同样的匹配规则和许可清单。匹配歧义或缺素材显示默认银行卡图标，不生成银行缩写假标志。测试浅色/深色背景对比度，尤其 Visa、Amex 和 Discover。

**主题：**新安装默认跟随系统，保留用户已有明确选择。iOS 的默认 light 可改为 system，但不能覆盖已有偏好。深浅色和皮肤色是两层设置；是否统一冰蓝/森绿等皮肤由产品体验决定，不强迫四端使用同一种布局或组件库。

**批量与图片：**先保证批量类别、年费状态/日期、有效期、删除确认的含义一致；同步已包含 cardImages，不需要重新发明图片字段。上传、删除、预览、缩略图与错误提示要逐端验收，尤其带图片同步、锁定时预览关闭及大图内存占用。

### 第三阶段：保留合理平台差异

Android 的 NFC 快速核对可作为手机增强能力；iOS 虽有源码，但默认工程排除读卡器且受编译开关控制，必须先确认权限、构建条件、设备和卡片协议，再决定启用，不能只删除 #if。macOS/Web 不必为了“同功能表”强行实现硬件读卡；可以通过图片辅助录入达成同一用户目标。

表格列自定义、桌面键盘导航、手机拍照和系统生物识别可各自原生实现。通知、后台刷新、离线可用性和权限拒绝也应按平台能力定义验收，而不是统一为一个“支持”勾选。

### 推荐交付顺序与验收

1. 先合并 Web 安全/正确性修复，并完成升级前后的合成备份往返与实际备份恢复演练。
2. 独立 PR 对齐四端计算、搜索、分组、排序与偏好持久化，带相同 JSON 期望结果。
3. 独立 PR 补收藏入口、品牌素材、默认外观及图片交互；收藏是否跨设备同步须作为单独协议决策。
4. 独立设备验收 NFC/OCR、生物识别、通知、后台切换及真实 WebDAV 的网络中断、并发修改、删除传播和恢复。

验收不只看页面是否有按钮：同一份数据在四端的金额、搜索结果、排序与同步合并应一致；平台不具备的硬件能力应明确标注，不用虚假入口凑齐。
