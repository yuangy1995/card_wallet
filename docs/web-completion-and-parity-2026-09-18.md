# Web 剩余问题修复与四端对齐方案

## 基线、范围与合并顺序

本次接续 PR #5（`ca0eb54dc5fd6ea976ee39d8b8549a040eadda9e`），在 `codex/web-security-performance-completion` 实现，PR #6 暂以 #5 分支为基线。先合并 #5，再把 #6 的目标分支改为 main 并核对差异；不要把两轮修复当成互斥替代方案。没有直接修改或合并 main，没有发布应用。

本次只修改 Web、相关测试和文档，不修改 Android/iOS/macOS 源码、应用标识、签名材料或 SyncV4 写入协议。上一轮审查报告保留为历史记录；其中“仍未修复”描述的是当时状态，本轮对应修复以本文及 PR #6 最终 Checks 为准。“已修复”不表示已经证明不存在其他缺陷。

## 已落实的修改

### 额度、日期和数据正确性

- `cardMetrics.js` 统一分组与统计页额度算法：共享额度按地区、规范化银行名和币种分池取最大值，独立额度累加，储蓄卡不计入。修复统计页取第一张共享卡、不同币种直接相加及组头统一显示 ¥ 的错误。
- 未知币种单列，不自动冒充 CNY，也不暗示已经进行了汇率换算。独立额度以分累加，避免常见浮点小数求和误差；没有引入实时汇率功能。
- 新增共享卡继承同口径卡片中的最大额度，而不是取列表中的第一张；避免新增卡片把同组额度意外降为较小值。相关提示明确限定同地区、同银行、同币种和共享卡。
- 表格合并只针对当前页中连续、同口径且同显示值的单元格，不跨独立卡、币种或分页边界。
- 列表、卡面和优惠用卡共用免息期计算，处理短月份实际账单日和当天消费归属；补齐按卡等级分组及免息期双向排序。
- Web 卡组织展示共用识别函数，歧义文本返回未知。它是展示提示，不是完整 BIN、发卡行归属或持卡权验证。离线品牌素材的四端统一仍属于后面的实施建议。
- 修复短卡号掩码、仅输入卡号分隔符时匹配全部卡片的问题。
- 同一卡片连续本地修改使用严格晚于已观察版本的时间戳，避免同毫秒修改由随机 mutationId 决胜而丢失新值；保持现有 SyncV4 冲突比较规则。

### 本地加密、迁移与锁定

- 卡片及图片所在业务数据、同步账本、历史、快照、WebDAV 账号密码和同步密钥以 AES-256-GCM 密文保存。每个保险库使用独立随机数据密钥；用户密码经随机盐和 PBKDF2-HMAC-SHA256（600000 次）派生包装密钥。运行时 CryptoKey 不可导出。
- 旧固定盐密码仅用于首次验证。正确验证后，在单个事务内迁移本地业务数据和历史配置，再移除旧密码校验值及凭证。迁移事务失败不删除原数据；残留密文缺少元数据时拒绝静默降级或覆盖。
- 加密已提交但旧凭证清理失败时，保留已提交保险库并清除运行密钥，返回密码解锁，不停留在首次设置页面或留下可用密钥。
- 保留数据库名 `card-wallet-web-local-db`，数据库版本升为 2，防止旧版版本 1 页面继续写入明文。旧页面阻塞升级时需要关闭后重试。版本变化关闭连接后会清除失效初始化状态，允许正确重新初始化。
- 已加密数据库的锁屏启动只读取小型元数据，不再 `getAll()` 载入整份密文和图片。首次旧库迁移仍完整检查数据；只有解锁后才读取、解密业务记录。
- 修改本地密码需要验证当前密码，只重新包装数据密钥，不重新加密全部图片，不改变云同步密钥；提交失败时原密码仍有效。
- 解锁前不挂载卡包界面或启动同步。每个新标签页必须取得自己的解密密钥，单独修改 localStorage 的“已解锁”标记不能取得解密权限。
- 锁定清除本地明文缓存和运行密钥、卸载业务界面及敏感弹窗、关闭消息、停止上传定时器并取消网络和系统认证请求。已被服务器接受的上传不能追溯撤回。
- 跨标签页按实际收到的锁定事件处理，而不是读取可能已经被后续解锁覆盖的存储值；接收锁定不再反向广播，避免相互重复锁定。即使业务界面尚未挂载，也取消在途解锁。重置本地数据前先锁定并通知其他标签页。
- 系统解锁使用 WebAuthn PRF 输出包装数据密钥，并验证凭证 ID、RP ID、挑战、来源、签名和用户验证标志。只验证签名的旧凭证不能解密；PRF 不可用时保留密码解锁，不退回明文密钥存储。
- 忘记本地密码不能恢复本地密文。明确确认后只重置本地数据，再设置本地密码，并手动提供原 WebDAV 配置及原同步密钥恢复云端快照；不自动删除远端备份。

安全边界：需要 HTTPS 或 localhost。静态加密不防御已解锁页面中的恶意同源脚本、恶意扩展或已被控制的操作系统；JavaScript 无法保证字符串即时从物理内存擦除，也不保证浏览器历史磁盘页的取证擦除。弱密码仍存在离线猜测风险。本地密码与云同步密钥用途不同，部署前应保留可用备份；迁移后不要直接回退只支持数据库版本 1 的旧代码。

### 同步可靠性与输入输出安全

- 数据库批量事务和账本队列让卡片、待同步标记和修改版本一起提交。通过版本比较拒绝陈旧标签页覆盖最新记录，并要求重新解锁加载最新版本。
- 连续本地编辑立即保存，0.8 秒内合并上传触发。下载期间的新编辑按最新账本合并，上传完成只确认对应修改版本，不会清除后续编辑的待同步状态。
- 设置页连接测试使用独立 WebDAV 客户端，关闭页面时取消，不替换正在同步的客户端，也不将尚未保存的地址用于业务同步。
- 用实际 AbortSignal、XHR 取消和超时替代库未采用的 fetcher 配置；加密准备阶段被取消后不再新发起上传。
- 任一选中云快照下载、解密或结构检查失败，都不发布不完整合并、不清理备份。仅清理本轮确实读入并合并的旧快照，保留其他设备在同步期间新增的文件。
- 保持 SyncV4 4.0.0 写入格式、310000 次云端 KDF 参数和文件命名。读取增加盐/IV 长度与合理工作量检查，拒绝极端参数。
- 移除浏览器无法兑现的“忽略服务器证书”开关；仍需要可信证书和正确 CORS，前端不能绕过浏览器校验。
- 用户动态 HTML 字段转义，图表 tooltip 使用富文本画布模式；CSV 处理逗号、引号、换行和危险公式前缀，空数据也能导出。
- 增加 CSP、no-referrer 和减少动态效果适配。connect-src 需要兼容用户自定义 WebDAV；部署方可进一步收紧，并在 HTTP 响应头设置 frame-ancestors，meta 不能替代它。

### 渲染、加载和响应式

- 主表格每页 50 行、卡片列表每页 24 张；统计长列表及优惠用卡也有分页。全量搜索、汇总、CSV 导出、跨页批量选择保留，不仅处理当前页。
- 选中 ID 使用 Set；选择清理只监听 ID，不深度遍历图片对象；折叠分组卸载卡片。清理图表、事件、计时器和失效组件引用。
- 使用一个共享日历日时钟刷新跨日计算，不为每张卡片创建计时器；移除人为增加的保存和分析延迟。
- Element Plus 与图表按需引入，不再强制把所有 UI 依赖放进巨大公共包。详情、编辑、帮助、同步等页面按打开需求加载；未打开统计时不加载图表。
- 桌面和手机工具栏按完整按钮组换行，避免文字/控件重叠。手机分页总数单列，首尾按钮不被挤出视口。保持现有配色、深浅主题和交互风格。

## 验证、性能口径与限制

本轮续审业务修复提交为 `028d12f6a980827bd67659538b5272b7f0b7c727`；真实双标签页浏览器回归补充于 `7821dd0308e149f25619346412c212d824e2cf9f`。本地全量测试为 **22 个文件、154 个用例通过**，相较 PR #5 的 85 个用例增加 69 个，保留已有测试。生产构建通过。临时补丁载荷及本轮临时工作流已移除。

单元/组件测试覆盖真实 Web Crypto、迁移回滚、密码修改、错误密钥及篡改、锁定后写入、旧标签页覆盖、WebAuthn PRF 与签名验证、部分云快照失败、连续修改竞态、共享额度继承顺序，以及锁屏仅读取元数据。真实 Vue/Element Plus 挂载测试以 2000 条数据检查 50 行/24 卡渲染上限。

`apps/web/scripts/browser-regression.py` 在 GitHub Actions 的真实 Chromium 中测试生产构建，使用 2000 张合成卡片并阻断外部请求。检查旧密码迁移后的密文存储、错误密码、全量搜索、跨页选择、渲染上限、图表按需加载、锁定销毁敏感弹窗、新标签页及刷新重新锁定、深浅主题、1440px/390px 工具栏不重叠和手机分页边界；还通过真实第二个标签页连续写入锁定/解锁标记，验证后到的解锁标记不能覆盖已收到的锁定事件。执行结果、截图及异常记录由 `Web quality` 上传为 `web-browser-regressions`。

最终 CI 结论必须对应 PR #6 最新提交的 Checks，而不是仅引用旧提交的通过结果。真实浏览器测试在 GitHub Actions 中执行；本地受管理浏览器的访问策略不作绕过。本地组件模拟不等于浏览器测试，WebAuthn 模拟认证器测试也不等于实体 Touch ID/Windows Hello 验证。

| --- | ---: | ---: |
| 入口静态 import 依赖 JS | 528.34 KB | 约 124 KB |

入口统计不含随后动态加载的密码对话框等页面，不等于首次交互全部网络字节；包体积下降不等于同等比例的页面提速。解锁包含必要密钥派生成本，完整卡片和图片仍消耗与数据量成比例的内存及存储，分页不代表可无限加载。

未执行真实 WebDAV 服务器端到端、实体生物识别/PRF 设备、Safari 等其他浏览器及四端实机互同步。验证前不把某个实现入口存在、单元测试通过或构建成功等同于所有平台互操作已经通过。

## 四端对齐实施方案

### 第一阶段：统一业务契约，不先改 UI

新增受版本控制的 `contracts/card-wallet/` 目录，建议包含 `schema.md`、`credit-limits.json`、`billing-dates.json`、`search.json` 和 `sync-cases.json`。这些是待实施建议，本 PR 未创建并声称四端已接入。四端分别读取同一份输入和期望结果，保留各端原生实现与独立构建，不为了复用引入跨端运行框架。

| 项目 | 具体修改 | 主要入口及验收 |
| --- | --- | --- |
| 共享额度/币种 | 同地区+规范化银行名+币种分池取最大，独立累加，储蓄卡排除；未知币种独立展示 | Web 本轮已统一；macOS `Domain/CardCatalog.swift` 空币种 CNY 回退应调整；Android/iOS 全部统计入口接样例，测试卡片顺序不影响结果 |
| 日期/年费 | 明确月末补齐、账单日当天消费归属、闰年、时区、到期边界；年费确认和下一次日期作为一次修改 | 四端 DateCalculator/CardReminderRules，列表/详情/统计/排序对同一张卡结果一致 |
| 同步语义 | 明确 ID、毫秒时间戳、修改版本、删除标记、恢复替换、图片和冲突规则 | 用离线并发、删除后旧设备恢复、损坏快照、时钟偏差和锁定中断等样例验证；不偷偷改变 SyncV4 |

四端最终互通验收应覆盖 4×3 个有向组合，至少包含新增、编辑、删除、恢复、图片和并发冲突。不能只测 Android 到 Mac 一个方向就认定四端对齐。

### 第二阶段：补搜索、分组、排序和偏好

| 平台 | 怎么改 |
| --- | --- |
| Android | 在 `ui/main/MainScreen.kt` 补免息期从短到长；搜索补齐权益、币种、地区、等级、额度等约定字段；保留原有偏好键与本机收藏 |
| iOS/iPadOS | `Features/HomeView.swift` 搜索补齐统一字段并规范化卡号；分组/排序由局部 `@State` 改为持久化；默认外观改 system，但不重置已有 light/dark |
| macOS | `Domain/CardCatalog.swift` 扩展搜索索引；修改空币种回退；检查根级分组/排序绑定是否跨启动保存。保留后台计算、取消过时任务和键盘导航 |
| Web | 本 PR 已补卡等级分组和免息期双向排序；保留表格/卡片与列定制，以相同契约覆盖两个视图，不重新复制业务算法 |

统一搜索字段为银行、别名、规范化卡号、等级、币种、地区、权益、备注、额度、类别。统一无分组/银行/地区/等级/卡组织；额度和免息期双向排序、最近修改，并用稳定 ID 处理平局。验收须检查实际菜单和结果，而不是只看枚举里是否有该选项。

### 第三阶段：共同操作、收藏与安全语义

- **收藏：**Android 当前是本机 SharedPreferences 展示偏好，不在 SyncV4。先给 iOS/macOS/Web 增加本机收藏/只看收藏，按稳定卡 ID 持久化，删除卡片时清理无效 ID。需要跨设备收藏时，单独设计偏好版本、合并、取消收藏和删除语义，不直接向 SharedCard 塞字段或因切换收藏更新业务时间戳。
- **图片与批量：**统一照片数量/MIME/大小限制、增删与预览、未知字段处理；所有平台明确“选择本页”与“选择全部结果”。验收跨页目标准确、图片往返不丢失、已删卡不复活、储蓄卡不出现信用卡专有动作。
- **提醒：**统一账单、还款、有效期和年费计算及去重；分别标明前台提醒与系统通知能力。关闭页面后的浏览器推送不是仅添加按钮即可获得，不能宣称四端完全相同的后台能力。
- **同步体验：**统一手动同步、待上传、失败重试、进度和历史脱敏、配置切换及锁定取消；保留各平台生命周期差异。
- **安全：**统一“锁定后敏感数据不可读、停止相关任务、清除敏感弹窗”的行为，各端使用对应安全存储。逐端审查数据库、附件和凭证的静态保护，不因有 Face ID/Touch ID 就推定所有文件已经加密。本地密码与云同步密钥保持区分。

### 第四阶段：统一素材和默认体验，保留原生优势

以 Android/macOS 的离线品牌目录为来源，建立资源清单、规范化匹配键、暗色变体和许可证记录，移植给 iOS/Web。匹配不确定时显示默认银行卡，不显示猜测品牌或缩写；品牌图案不作为 BIN 或所有权验证结果。

首次安装默认跟随系统，升级保留用户明确偏好。macOS 保留三栏和键盘操作，手机保留原生导航，Web 保留表格，不用相同布局强行替代所有端。

Android NFC/相机能力保留；iOS NFC 虽有源码，但默认 `project.yml` 排除读卡器且界面受编译开关控制，需独立核验目标设备、权限、卡片协议及发布能力后再启用。Web/macOS 不虚构等价硬件能力；这些合理平台差异不按普通功能缺失处理。

## 提交与验收建议

依次拆为四个可回归 PR：业务契约和核心规则 → 搜索/排序/偏好 → 收藏及图片/批量/安全语义 → 品牌素材与原生体验。每个阶段保留旧数据、旧同步文件和现有测试；维护 CI 门禁，并用相同 50/500/2000 张合成数据测量渲染、搜索、选择和图片处理。

最后在 Android、iPhone、iPad、Mac 与目标 Web 浏览器执行真实设备及服务器验收。建议实现不等于本 PR 已修改其他三端，也不以单一设备通过代替四端互操作。
