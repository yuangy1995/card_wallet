# 四端功能对齐实现与验收

基线为已合并 Web 修复的 `main@25e7f1760f8cb94745f349e4fa7921fbbe8bf36f`。本轮依次实现四个阶段，保留各端独立构建、原生布局、应用标识和本地数据位置。本文替代此前审查文档中的待实施计划；旧审查报告作为历史记录保留。最终检查结果以本轮 PR 的最终提交及合并后主分支 Checks 为准，不能把中途一次成功当作最终成功。

## 第一阶段：共同业务规则

`contracts/card-wallet/fixtures/` 的额度、账单日期、搜索、排序、同步冲突、年费和图片 JSON 由四端各自原生测试读取。没有新增跨端运行框架，也没有改变 SyncV4 写入结构或云端密钥派生参数。

- 共享额度按照地区、规范化银行和币种分池，取最大值；独立额度累加、储蓄卡不计入、未知币种单列。金额以分为单位处理常见小数误差。修复 iOS 统计取第一张共享卡和 macOS 空币种回退 CNY。
- 月末、闰年、账单日当天消费归属与无效日期由统一样例约束。列表、统计和排序调用本端同一规则实现。
- 年费确认不重复推进已确认的周期；批量操作保留没有更新的字段与已有图片。信用卡专有更新不作用于储蓄卡。
- 同一张卡的连续修改时间严格晚于已观察版本。现有删除记录和冲突排序保持兼容，测试覆盖合并顺序、幂等性、序列化往返和删除优先关系。

入口：Web `utils/cardCatalog.js` / `cardMetrics.js` / `cardReminderRules.js`，Apple `Domain/WalletCardRules.swift`，Android `utils/WalletCardRules.kt`。契约不是各端运行时复制数据的替代品；实际服务器互通的验收边界见后文。

## 第二阶段：搜索、排序和偏好

四端搜索银行、别名、规范化卡号、等级、币种、地区、权益、备注、额度、类别和卡组织展示提示。仅输入卡号分隔符不匹配所有卡片。补 Android 免息期升序；无效日期统一放最后，排序平局使用稳定 ID。Web 表格与卡片共用排序配置。

iOS 分组和排序使用持久化偏好；macOS 根级偏好持久化；Android 保留原有键；Web 保留已有表格、卡片、列定制和分页。数据计算不因为分页缩小到当前页。系统日期变化时重新计算日期相关结果，不为每张卡创建独立高频计时器。

## 第三阶段：本机收藏、图片与数据保护

### 收藏和图片

Android 原有本机收藏保留，iOS、macOS 和 Web 增加收藏及只看收藏。使用稳定卡片 ID，删除后清理失效 ID，单纯收藏不更新业务修改时间，也不向 SyncV4 增加字段。Web 收藏保存在本地加密存储，写入成功才更新显示；存储失败不伪装成功。**本机收藏不跨设备同步。**

新增图片遵循 `card-images.json`：统一输入数量、字节数、存储字节数与最大边长限制；验证图片能够解码，再生成受控的 JPEG。历史附件不在普通编辑时偷偷重压缩或删除。预览沿用原生端现有组件，Web 大列表仍限制挂载数量。超限和无效输入有明确提示，不会把损坏数据当作可用图片。

### 原生本地存储

- Android 在原 `card_wallet.db` 升级至版本 4。卡片及同步记录使用 AndroidKeyStore 中的独立 AES-GCM 密钥加密，密文按小块保存，避免图片超过单行读取窗口限制。旧明文迁移、版本更新和清理置于 SQLite 事务中；失败回滚。AAD 绑定记录用途与分块，拒绝替换或损坏的密文。`secure_delete` 用查询 API 正确启用。
- macOS 卡片、同步账本、同步历史迁移到本机随机密钥保护的密文；密钥由钥匙串保管。仅旧格式读取保留兼容路径，新写入不再使用固定口令。密文或账本损坏时保留原文件，停止同步，不以空账本覆盖。
- iOS 保留既有本地加密格式和钥匙串位置，强化密钥缺失、长度错误与读写失败处理；发现已有密文时不重新生成密钥覆盖。云端读取检查盐、IV 和 KDF 工作量，写入参数不变。
- 本地保护与云同步密钥分离。锁定卸载敏感界面、清理本机展示状态并取消同步请求；陈旧异步任务不得在锁定后重新发布结果。取消不能撤回服务器已接受的请求。

这是静态存储与生命周期保护，不是声称防御被控制的操作系统、恶意调试器，或保证旧磁盘页的取证擦除。原生系统认证、系统安全存储与 Web 密码保险库的技术实现不同。

## 第四阶段：统一离线品牌与主题

`scripts/sync-wallet-brand-assets.py` 从 Android 已有的品牌目录、WebP 与 macOS 已有的 PNG 资源生成 iOS/Web 资源。保留原始像素、透明度、比例及许可证；不从新的在线 Logo 服务下载素材。`--check` 校验提交的字节、资源清单与陈旧文件，CI 不会自动写回主分支。

当前目录有 374 个机构条目和 7 类卡组织，不代表覆盖所有银行。iOS、Web 的银行及卡组织组件实际接入卡片、列表/表格和已有详情入口；macOS 继续使用 PR #4 的原生组件。四端使用共同的 `branding.json` 约束繁简体、英文别名、歧义、卡号长度与号段边界。明确且无歧义的等级提示优先，多提示回退卡号规则；未知银行或素材加载失败显示通用银行卡，不显示缩写，不冒用另一银行。识别结果不是 BIN 查询或持卡权验证。

首次安装跟随系统主题，旧用户已存选择不重置。iOS 卡片宽度改由父容器决定，适配 iPad 分屏。保留原有配色、间距、导航及 Mac 三栏/键盘、Web 列定制。新 Apple 文案补中英文/繁体资源；Android 维护已有国际化资源。

## 自动验收入口

- Web：`cd apps/web && pnpm test:run && pnpm build`；安装 Playwright Chromium 后运行 `python scripts/browser-regression.py` 和 `python scripts/parity-browser-regression.py`。
- Android：`cd apps/android && bash gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`；模拟器上运行 `:app:connectedDebugAndroidTest`，包括实际 AndroidKeyStore 的加密、跨实例读取、密钥丢失和篡改保护。
- Apple：在各端目录 `xcodegen generate` 后，以相应 Xcode scheme 执行 `xcodebuild test`。提交了新增源文件、资源和测试的工程登记。CI 使用模拟器/临时测试签名参数，不修改正式签名。
- 素材：`python3 scripts/sync-wallet-brand-assets.py --check`。新测试检查全部打包素材加载，输出原生深浅主题及大字体截图。
- 只读自动流程：`.github/workflows/platform-quality.yml` 与原有 Web/Android 检查。临时传输目录、源代码应用脚本与写回工作流不进入最终版本。

Web 保留原有 2000 张合成卡的大列表、跨页选择、全量搜索、加密迁移、多标签页锁定与布局测试；新增真实页面的收藏重启保留、取消收藏、同源素材加载、失败回退及桌面/手机深浅主题检查。

## 升级与尚需设备环境的验收

部署前保留可用的加密云备份及其同步密钥。原生端存储迁移后不要直接回退到只理解旧明文/固定口令格式的版本；Web 数据库版本 2 的回退限制仍有效。不要在保留密文的情况下清除系统密钥库。遇到读取失败，先保留原数据；本轮没有自动删除远端备份或替用户重置本机数据。

自动测试不等于实体 Face ID/Touch ID、硬件安全模块或真实 WebDAV 厂商服务器验收。AndroidKeyStore 测试在 Android 模拟器实际运行时执行，不宣称硬件背书。iOS 原生界面渲染不是完整 iPhone/iPad 真机交互测试；Web Chromium 不代表 Safari/Firefox 已测。

共同契约测试包含四端独立实现的相同输入和序列化结果，但不把它称为真实服务器的 12 个有向同步组合。上线验收仍需用隔离的测试 WebDAV 目录对 Android、iOS、macOS、Web 两两进行新增、编辑、删除、图片、恢复与并发修改，核对最终记录与附件。iOS NFC 保持默认关闭；Android NFC 保留；没有伪造 Web/Mac 等价读卡硬件能力。
