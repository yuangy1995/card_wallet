# 四端功能对齐实现与验收

基线为已合并 Web 修复的 `main@25e7f1760f8cb94745f349e4fa7921fbbe8bf36f`。本轮依次实现四个阶段，保留各端独立构建、原生布局、应用标识和本地数据位置。旧审查报告作为历史记录保留；本轮实现以本文为准。最终检查结果见 [PR #7](https://github.com/yuangy1995/card_wallet/pull/7) 的最终提交及合并后主分支 Checks，不能把中途一次成功当作最终成功。

## 第一阶段：共同业务规则

`contracts/card-wallet/fixtures/` 的额度、账单日期、搜索、排序、同步冲突、年费和图片 JSON 由四端各自原生测试读取。没有引入共享运行框架，没有改变 SyncV4 写入结构或云端密钥派生参数。

- 共享额度按照地区、规范化银行和币种分池取最大值；独立额度累加、储蓄卡排除、未知币种单列，以分为单位处理常见小数误差。修复 iOS 统计取第一张共享卡和 macOS 空币种回退 CNY。
- 月末、闰年、账单日当天消费归属与无效日期由共同样例约束；列表、统计和排序调用本端同一规则实现。
- 年费确认不重复推进已确认周期；批量操作保留没有更新的字段与已有图片。信用卡专有更新不作用于储蓄卡。
- 同一卡片连续修改的时间严格晚于已观察版本；删除记录和冲突排序保持兼容。测试覆盖合并顺序、幂等性、序列化往返和删除关系。

入口：Web `utils/cardCatalog.js` / `cardMetrics.js` / `cardReminderRules.js`，Apple `Domain/WalletCardRules.swift`，Android `utils/WalletCardRules.kt`。共同契约不能替代实际服务器的互通验收。

## 第二阶段：搜索、排序和偏好

四端搜索银行、别名、规范化卡号、等级、币种、地区、权益、备注、额度、类别及卡组织展示提示。仅输入卡号分隔符不匹配全部卡片。补 Android 免息期升序；无效日期统一放最后，排序平局使用稳定 ID。Web 表格与卡片共用排序配置。

iOS 分组和排序持久化；macOS 根级偏好持久化；Android 保留原有键；Web 保留表格、卡片、列定制和分页。分页不把全量搜索和统计变成仅当前页。系统日期变化时重新计算日期结果，不为每张卡创建高频计时器。

## 第三阶段：收藏、图片和数据保护

### 收藏和图片

Android 原有本机收藏保留，iOS、macOS、Web 增加收藏及只看收藏。使用稳定 ID，删除后清理失效 ID，收藏不更新业务修改时间，不向 SyncV4 增加字段。Web 收藏存入本地加密存储，提交成功才更新显示。**收藏仍是本机偏好，不跨设备同步。**

新增图片遵循 `card-images.json` 的数量、输入字节、存储字节和最大边长限制；检查可解码后生成受控 JPEG。历史附件不在普通编辑时重新压缩或删除。预览沿用现有组件，超限或无效输入明确提示，Web 大列表保持挂载数量上限。

### 本地存储：四端实现不相同

| 平台 | 本轮保护方式 | 重要边界 |
| --- | --- | --- |
| Android | 原 `card_wallet.db` 升到版本 4；AndroidKeyStore 独立 AES-GCM 密钥；卡片/同步记录密文分块；旧明文迁移及版本更新在 SQLite 事务中完成，失败回滚 | 密钥不可导出；密钥丢失后拒绝默默生成新密钥。模拟器验证不等于硬件安全模块背书 |
| iOS | 保留既有本地加密格式和钥匙串位置；强化密钥缺失、长度错误与读写失败；已有密文时不生成替代密钥 | 云端读取增加盐、IV 与 KDF 工作量校验；写入参数不变 |
| macOS | 沿用既有 `appInternal` 凭证存储选择，不新增系统钥匙串授权；卡片、账本和历史使用随机本机密钥 AES-GCM，密钥文件位于原应用目录并设为仅当前用户可读写 | **不是钥匙串保险库，也不是密码派生保险库；复制密文及其密钥文件的人仍能解密。** 不宣称对整份应用目录被复制提供保密性 |
| Web | 继续使用此前已合并的本地密码保险库，并将收藏纳入加密存储 | 本地密码与云同步密钥分离；锁定清除运行密钥与敏感界面 |

Android 分块避免大图片超过单行读取窗口，AAD 绑定记录用途和分块，拒绝替换或损坏密文；`secure_delete` 通过查询 API 正确启用。macOS 仅旧格式读取保留兼容路径，新写入不再用固定口令；损坏账本保留原文件并停止同步，不能以空账本覆盖。

锁定卸载敏感界面、清理展示状态并取消同步请求；陈旧任务不得在锁定后重新发布结果。取消不能撤回服务器已接受的写入。上述保护不防御已被控制的操作系统或恶意调试器，也不保证旧磁盘页取证擦除。

## 第四阶段：离线品牌与主题

`scripts/sync-wallet-brand-assets.py` 使用 Android 已有目录/WebP 与 macOS 已有 PNG 生成 iOS/Web 资源；保留原始像素、透明度、比例和许可证，不使用新的在线 Logo 服务。`--check` 校验提交字节、清单与陈旧文件，CI 不自动写回。

目录目前含 374 个机构条目、7 类卡组织，不代表所有银行。iOS/Web 组件实际接入卡片、列表/表格及已有详情入口；macOS 继续使用 PR #4 原生组件。四端运行同一份 `branding.json`，覆盖繁简体、英文别名、歧义、长度和号段边界。明确无歧义的等级提示优先，多提示回退卡号；未知银行或素材加载失败显示通用银行卡，不显示缩写，不冒用另一机构。品牌提示不是 BIN 查询或持卡权验证。

首次安装跟随系统，旧用户选择不重置。iOS 卡片宽度由父容器决定，避免使用物理屏幕宽度破坏 iPad 分屏。大字体模式使用紧凑卡号掩码，确保末四位不会被掩码挤出。保留现有配色、间距、导航、Mac 三栏/键盘与 Web 列定制。新 Apple 文案补英文/繁体资源，Android 更新既有国际化。

## 自动验收

- Web：`cd apps/web && pnpm test:run && pnpm build`；安装 Playwright Chromium 后执行 `python scripts/browser-regression.py` 与 `python scripts/parity-browser-regression.py`。
- Android：`cd apps/android && bash gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug`；模拟器执行 `:app:connectedDebugAndroidTest`，检查实际 AndroidKeyStore 加密、不可导出、跨实例大记录、篡改和密钥丢失。
- Apple：各端 `xcodegen generate`，对应 scheme 执行 `xcodebuild test`。新增源文件、资源和测试已登记工程。CI 使用临时测试参数，不修改正式签名。
- 素材：`python3 scripts/sync-wallet-brand-assets.py --check`；检查全部打包图像加载，输出原生深浅主题及大字体截图。
- 流程：`.github/workflows/platform-quality.yml` 与已有 Web/Android 检查。临时传输目录、代码应用脚本和写回工作流已移除。

保留 Web 原有 2000 张合成卡的大列表、跨页选择、全量搜索、迁移、多标签页锁定和布局测试；新增收藏重启保留、取消收藏、同源素材、失败回退及桌面/手机深浅主题检查。测试、构建和模拟器分别报告，不把其中一种当作其他检查的替代品。

## 升级与设备验收边界

部署前保留可用加密云备份及同步密钥。原生迁移后不要直接回退到只理解旧格式的版本；Web 数据库版本 2 的回退限制仍有效。不要在保留密文时清除系统密钥库或 macOS 本机密钥文件。读取失败先保留原数据；本轮没有自动删除远端备份或替用户重置本机数据。

自动测试不等于实体 Face ID/Touch ID、硬件安全模块或真实 WebDAV 厂商服务器验收；iOS 组件渲染不是完整 iPhone/iPad 真机交互，Chromium 不代表 Safari/Firefox 已测。macOS 的应用内部密钥模式保持既有产品行为，若要抵御整目录拷贝，应另行明确系统钥匙串授权或密码派生密钥的产品策略及迁移方式。

共同样例包含四端独立实现和序列化结果，但不称为真实服务器的12个有向同步组合。上线验收仍需在隔离 WebDAV 目录上两两执行新增、编辑、删除、图片、恢复和并发修改。iOS NFC 保持默认关闭，Android NFC 保留，不虚构 Web/Mac 等价硬件能力。
